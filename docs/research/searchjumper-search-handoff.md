Researched 2026-10-28 against primary source. This is source inspection, not a claim that SearchJumper was exercised in a browser.

## Verified behavior

### Capture and transfer

1. The current default Google rule matches Google `/search` pages and explicitly extracts keywords from `textarea[name='q']` ([config](https://github.com/hoothin/UserScripts/blob/75eab206f6af48b29291ba6b4022d48f682d964e/SearchJumper/searchJumperDefaultConfig.js#L959-L966)). `getKeywords()` first considers selected text, then configured keyword rules. A DOM rule reads `value || innerText`; URL query extraction from the engine's URL template is in the alternate branch used when there is no configured keyword rule. Successful reads update `localKeywords` ([complete function](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L15076-L15164)). Thus this configuration can read live input state rather than only the initial URL.
2. Selecting a current search engine clears local keyword state, refreshes `cacheKeywords`, and stores the search page's hostname as `referrer`. `updateCacheKeywords()` reads `getKeywords()` and persists a changed nonempty value ([functions](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L9217-L9234)).
3. Capture-phase **click and auxclick** handlers on the body refresh cached keywords and store `clickLink` when a recognized engine is active ([handler](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L15880-L15903)). This refresh happens at link activation, including the middle-click event path. The implementation has a 300 ms throttle, checks only an anchor or its immediate parent, and in the parent branch writes `_t.href` rather than the parent's href. These limitations should not be copied; deeper result-link descendants are not covered by this handler.
4. The storage adapter uses extension storage, `GM.getValue`/`GM.setValue`, or `GM_getValue`/`GM_setValue` when available; its fallback includes site-local `localStorage`. It explicitly identifies the GM APIs as cross-save support ([adapter](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L1435-L1506)). Startup loads `cacheKeywords`, `referrer`, and `clickLink` from storage ([initialization](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L18748-L18781)). This is the ordinary search-result transport; it does not need to append search terms to every result URL.
5. On a non-engine top-level page, `checkSearchJump()` accepts cached keywords when automatic search-result highlighting is enabled and the referrer contains the stored source hostname. If `document.referrer` is empty, it instead accepts a stored `clickLink` contained in the destination URL and clears that stored link. Global in-page words are a separate fallback ([destination logic](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L8930-L8967); [startup call site](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L8668-L8683)). Matching uses string containment, not strict URL identity. There is no timestamp/TTL check in this handoff path, and these are single shared storage values rather than a per-destination queue.

The default settings enable highlighting on search-result destination pages and disable highlighting on the search engine itself ([defaults](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L163-L167)). Destination highlighting waits for complete document readiness, adds a 300 ms delay, and defers processing while the document is hidden ([complete scheduling method](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L8840-L8880)). These are timing choices, not evidence that every site's delayed content works.

### Tokenization

`searchEngineWords()` removes tokens beginning with `-` at the start or after an ASCII space; rewrites quoted content with `◎` separators using a **greedy** quote expression; and replaces remaining apostrophes, quotation marks, and semicolons with spaces ([complete method](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L8829-L8838)). The destination enables word mode before using that transformation.

`submitInPageWords()` normally chooses `◎` as the separator. `anylizeInPageWords()` in word mode splits on that separator **or ASCII space**, sorts longest terms first, trims them, and applies configured minimum length and ignored words during initial automatic highlighting ([parser](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L5199-L5302); [submission setup](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L5304-L5348)). This does **not** establish reliable quoted-phrase preservation or complete Google operator parsing; the implementation should not be described that way.

### `#sjhl` is a separate permalink mechanism

Holding a SearchJumper highlight for 800 ms rewrites the current URL to `#sjhl=<encodeURIComponent(original-word)>&i=<1-based-match-index>` ([generation](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L6597-L6623)). Startup recognizes this exact leading marker, decodes its text, calls the in-page highlighter, and scrolls the selected `mark.searchJumper` into view ([consumption](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L8685-L8701)). It carries in-page input syntax and an optional index. It is not the normal Google result-click handoff described above.

### Live navigation

The body mutation observer compares the current URL with the previous URL on relevant mutations and calls a debounced refresh when they differ. It separately processes inserted text for active highlight words ([observer](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L15946-L16033)). `refresh()` can reread engine keywords and rehighlight after a delay ([method](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L9236-L9329)). Although history wrappers are defined, their `history.pushState` and `history.replaceState` assignments are **commented out** ([listeners](https://github.com/hoothin/SearchJumper/blob/af4a0fbbec7f154a72cc7658ab865fa3fda65e11/searchJumper.user.js#L15904-L15923)). Do not attribute active history interception to this snapshot. Activation-time keyword capture is the clearer transferable safeguard against stale initial search state.

## Implications for Slim Search Highlight

The local baseline stores `hl_cross_terms` only in the initialization call to `updateCrossPageTerms()`. Its mutation observer and popstate/hashchange handlers refresh highlighting/page identity but do not refresh that shared search-query cache. A Google search updated without reinjecting the userscript can therefore leave old terms in storage. Referrer extraction cannot reliably repair that: the default browser policy sends only the origin on ordinary cross-origin navigation, removing `/search?q=...`, and stricter policies can omit the referrer entirely ([W3C default and no-referrer](https://github.com/w3c/webappsec-referrer-policy/blob/cc435b05ca4a94f7f1a139be5074b168d20014db/index.src.html#L240-L263); [cross-origin behavior](https://github.com/w3c/webappsec-referrer-policy/blob/cc435b05ca4a94f7f1a139be5074b168d20014db/index.src.html#L453-L496)). This is a browser-policy limitation, not evidence of a particular live Google response header.

Recommended implementation direction, derived from the inspected behavior rather than copied code:

- Refresh the shared query snapshot immediately before result navigation using capture-phase link activation; support ordinary, modified and middle clicks without preventing native navigation. Resolve links with `closest('a[href]')` rather than SearchJumper's shallow parent checks. Do not use arbitrary page selection as automatic query input.
- Reconcile live search state when location changes. Prefer an authoritative current search URL when available; use an explicitly scoped engine input fallback only where needed and guard against unsubmitted edits becoming the wrong result query.
- Keep privileged shared storage as the cross-origin transport. Preserve bounded expiry and user opt-out behavior; avoid depending on a full referrer URL. If introducing destination correlation, use normalized URL matching and consider concurrent search tabs, empty queries, and redirects rather than copying a global substring match.
- Treat tokenization independently from transport. Existing whitespace-only parsing leaves quotes/operators attached to terms; decide and test supported syntax explicitly. SearchJumper supplies a useful negative-term example, not a complete query grammar.
- Preserve existing `#hl` and `#sjhl` compatibility intentionally. The local baseline splits decoded marker values on commas or plus signs; SearchJumper's marker contains its own in-page term syntax plus a match index. Do not silently conflate permalink parsing with automatic search-term tokenization.

Useful regression cases: initial Google query; Google query changed via SPA navigation before clicking a result; full, origin-only, and empty referrers; ordinary/Ctrl-or-Cmd/middle-click navigation through deeply nested link content; URL-only query changes; opt-out; expired storage; concurrent search tabs; a query that becomes empty; and marker compatibility.

## Local implementation and verification (4.4.1)

The fix refreshes the submitted URL query at native link activation and uses a search-field fallback only when URL query parameters are absent. It keeps the existing ten-minute TTL, adds versioned per-destination records capped at twelve entries, preserves opt-out and unknown schemas, and does not rewrite result links. These choices are derived from the inspected behavior; SearchJumper code was not copied.

[Browser regressions](../../tests/suites/search-handoff.cjs) cover source/query updates, expiry, origin-only and absent referrers, nested/modified/context-menu activation, Google redirect wrappers, unrelated destinations, concurrent tabs and storage failures. Two tests additionally perform actual same-tab and middle-click navigation between local HTTP origins, using a shared GM adapter and the browser's real `no-referrer` policy. This verifies native browser navigation on controlled pages; it is not a claim of testing a live Google response or a real Tampermonkey/Violentmonkey installation.
